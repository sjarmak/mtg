# Agent Instructions

## Project Orientation

MTG set-generation and playing lab. Goal-of-record: `docs/design-brief.md`. Engine strategy (decided in `docs/research/decision-synthesis.md`, ADR pending as bead `mtg-bc2.1`): build-first hybrid — custom strict-TypeScript event-sourced rules kernel + typed mechanics DSL as the core; Forge at arm's length (subprocess only, GPL — never vendored) as parity oracle, DSL transpile/export target, and early human play surface; XMage/Argentum (MIT) mined as reference designs for layers/replacement subsystems; LLM referee handles only framed, schema-constrained rulings while the kernel owns all state.

Load-bearing invariant: the set generator's output space stays inside the engine's enforceable space — cards are emitted in the DSL, never free text the engine can't run. Inside, not equal to: `ModelAbilityIsAbility` and `ModelEffectSchema` prove containment at compile time, and the containment is deliberately strict in places (`putCounters` is expressible by hand and unreachable from the generator). Equality is the direction that fails loudly and nobody wants; containment is the one that keeps a generated card runnable.

Stack: strict TS throughout. Prior-art evidence: `docs/research/` (six `prior-art-*.md` lane reports, two proposals, `decision-synthesis.md`). Conventions: ZFC (judgment to models, plumbing in code); balance as CI assertions (seeded sims, win-rate bands); sim logs as a 17lands replay-schema superset; GPL/AGPL behind process boundaries with a CI grep guard; non-commercial under the Wizards of the Coast Fan Content Policy, whose notice `README.md` carries.

## Codebase Conventions

**Workspace layout.** npm workspaces, one package per bounded concern under `packages/<name>/` with `src/` and `test/`. Cross-package imports use the workspace name (`@mtg/dsl`), never relative paths across package boundaries.

Every package's `package.json` follows this template exactly (source-resolved, no build step in dev):

```json
{
  "name": "@mtg/<name>",
  "version": "0.0.0",
  "license": "MIT",
  "type": "module",
  "main": "./src/index.ts",
  "exports": { ".": "./src/index.ts" }
}
```

Declare cross-package deps as `"dependencies": { "@mtg/dsl": "*" }`.

**Dependencies are pre-installed at the root** (zod, @anthropic-ai/sdk, better-sqlite3, vitest, tsx, typescript, eslint, prettier). Do NOT run `npm install` — concurrent installs race on the lockfile. If a package genuinely needs a new third-party dep, report it instead of installing.

**Tooling.** Root configs only; packages carry no tsconfig/vitest/eslint config of their own. `npm run typecheck` (strict, `noUncheckedIndexedAccess` + `exactOptionalPropertyTypes` are on), `npm test` (vitest, `packages/*/test/**/*.test.ts`), `npm run test:balance` (seeded format-health gate, `packages/metrics/test/balance/`), `npm run lint`, `npm run format`. The tsconfig `include` also covers `packages/*/tools/**/*.ts` and `packages/*/*.config.ts`, because those were once outside it and were hiding a real type error.

**Some gates do not live in the package they judge, so run the whole suite before you commit.** `npm test` is the gate; `npx vitest run packages/<yours>` is a convenience and is not the same check. The clearest case is spelling: `packages/slice/test/spelling.test.ts` scans test and doc files across every package, so a British spelling in a `packages/dsl` docblock is invisible to four consecutive green `packages/dsl` runs and fails only when the suite runs whole. That is not hypothetical: `kernel/chests-and-flurry` was committed with a British spelling of "pluralize" in a new test docblock after exactly that sequence, and the fix is `57a31bd`. One corollary, learned writing this paragraph: never quote an offending spelling to illustrate the rule. The scanner reads a quotation as a use and fails the file, so name the word and describe the error instead of reproducing it. `packages/slice/test/workspace-roster.test.ts` is the same shape one level up: it fails in `slice` when `packages/` gains a directory. If a run is too slow to repeat, run the whole suite once at the end rather than never.

The spelling gate had a second edge, and it was worse than the first because the suite reported green rather than not running: the scanner read the files git knows about, so a file that was still untracked was invisible to it. Write a new test file, run the whole suite, watch it pass, then `git add` and commit, and the gate never read the file it was now responsible for. `aea0184` is that sequence: two spellings in the wrong dialect rode into `18fca10` behind a full green run, and surfaced only when a later branch was gated in a worktree of its own. **Both gates now read the working tree rather than the index** — the spelling scanner and the export's boundary gate alike (`mtg-gq2j`), each listing with `--others --exclude-standard` so `.gitignore` still holds. Staging order is no longer part of the check. The spelling scanner's own docblock argues why this is not the untracked-state defect the `verify:art` rule is about.

**One agent per working tree.** Dispatching several agents at one checkout is the same class of mistake one level up: every gate any of them runs measures the union of everybody's half-finished edits, so a green suite is evidence about a mixture and about no branch in particular. Give each lane `isolation: "worktree"`, or verify each branch afterwards in a worktree of its own — `git worktree add <dir> <branch>` plus a symlink to the root `node_modules`, which works because the vitest configs resolve `@mtg/*` through `resolve.alias` to the worktree's own sources rather than through `node_modules`.

**A red test names the machine it went red on.** Under a wave of lanes this box runs at several times its core count, and past that point vitest's 5s default measures the queue rather than the code: a different file every wave, every one of them passing alone. The flake is cheap; the misattribution is not, because the agent who reads the red pays a round of work proving their diff is innocent. So `packages/slice/tools/test-load/` makes a timeout say which it was. Every run prints one line naming the cores, the pool size and the peak 1-minute load. Every timeout carries a verdict **on the error itself**, since vitest prints the failure dump last and that dump is the first thing anybody reads: `LOAD` past twice the cores or a quarter second of scheduling lateness in the collating process, `NOT LOAD` on a quiet machine, `MAYBE LOAD` between them, each with the numbers behind it. **The run is part of the load it is reading** (mtg-es2): the collator subtracts its own test files in flight before blaming the outside, and a run holding half the cores in files of its own reads `MAYBE LOAD, FROM THIS RUN ITSELF` rather than quiet. Before that it read a peak of 7.3 on 16 cores, produced by its own 15 workers, and told the reader the machine was quiet and the failure was theirs. A run that nothing outside it held off the cores also names every test that spent over half its budget, which is the population that times out next; that list is suppressed when the collating process was itself kept waiting, because on a borrowed box every test looks slow and the reading says nothing about any of them.

**A gate's exit code is a function of its assertions, including when the two processes lose each other.** Vitest's worker gives the collating process 60 seconds to answer each birpc call, that deadline is compiled into the installed dist with no config option pointing at it, and a starved collator therefore turns into `[vitest-worker]: Timeout calling "onTaskUpdate"`, an unhandled error, and exit 1 on a run whose every assertion passed. `npm run test:balance` did exactly that three times on 2026-08-20 while judging the flagship set fair (mtg-c9bc); its single cases run 200 to 400 seconds, so one worker holds a task open far past the deadline. `packages/slice/tools/test-load/rpc-timeout.ts` is the second reporter in `vitest.config.ts`: it names that failure on stdout and clears the exit code when, and only when, every unhandled error is a reporting-channel timeout, vitest judged the run passed, and every module and every collected test reported a result. The last two conditions are the point — the call that timed out is the one carrying results, so a run that cannot account for all of them is the run that must keep its red. It can turn a 1 into a 0 and never the reverse, and `--reporter` on the command line replaces the configured list, so a run given one gets vitest's exit code and not this verdict.

The same directory sizes the run's own pool, and the reason is measured rather than assumed. Four interleaved `--project unit` runs during a five-lane wave (load in the forties on 16 cores): halving the pool from vitest's `cores - 1` to eight costs about a quarter of the wall clock and takes 40% off the p99 test duration (465ms and 518ms down to 292ms and 303ms), with the count of default-budget tests running inside 7x of their budget falling from 19 and 23 to 12 and 12. Under contention a worker is not throughput, it is one more claim on cores already spoken for. So `maxWorkers` is sized against the load that was already on the machine when the config was evaluated, and **a quiet machine is unchanged** — CI and a lone developer keep `cores - 1` and the wall clock that comes with it. `MTG_TEST_WORKERS` pins it when a reading has to be reproduced. None of this raises a timeout: every test still fails at exactly the number its own call site states, and `packages/slice/test/test-load.test.ts` fails if `vitest.config.ts` ever names a clock outside the balance project.

**`maxWorkers` bounds the forks and says nothing about what a fork then starts.** Sampling the process tree of one `npm test` four times a second (mtg-czt) found **103 to 130 runnable threads of its own** at the peak, on 16 cores, before any other lane is counted: two vitest instances rather than one, because `gate-wiring.test.ts` starts the gate again as a child process, with fifteen forks each — and four of those forks each holding a **16-thread sim pool**. Five files can reach for a default-width pool in one run (`format-health`, `broken-set`, the nested gate run, `closing`, and `packages/ui/test/analysis/round-trip.test.ts`), and none of them was greedy: each asked for `availableParallelism()` and each was told yes. So `packages/sim/src/pool-size.ts` conditions the default on where the caller is standing. A pool whose own process is a vitest worker takes a quarter of the cores, floored at two; **every other caller takes the whole machine exactly as before** — `npm run slice`, the CLI, an operator's sweep — and a width a caller states is never touched. `MTG_SIM_WORKERS` pins it when a reading has to be reproduced. **That count is now an instrument rather than a paragraph**: `MTG_SIM_POOL_CENSUS=<file>` makes every pool in every process append its open and its close to one timeline, and `censusOf` turns that back into the peaks (`packages/sim/src/pool-census.ts`). It is off unless the variable names a file, and costs one environment lookup per pool when off. Re-measured with it on 2026-08-16: five default-width pools live at once across both projects, but **two** in `--project unit` and never both at once, and that is the population that times out.

Full `npm test`, three widths rotating on a near-idle box (each started under load 25, two runs apiece, medians):

| pool                 | wall | peak runnable, own tree | p95   | p99    | inside 3x | inside 7x |
| -------------------- | ---- | ----------------------- | ----- | ------ | --------- | --------- |
| 16 (the old default) | 80s  | 111                     | 266ms | 1147ms | 28        | 83        |
| 8                    | 73s  | 72                      | 215ms | 821ms  | 18        | 57        |
| 4 (a quarter of 16)  | 70s  | 58                      | 170ms | 606ms  | 11        | 34        |

The tail falls the whole way down and the wall clock does not pay for it. Under a wave the gap widens: three paired runs alternating 16 against 4, each started around load 30, went 105s to 83s of wall clock with p99 1215ms to 643ms, and three tests timed out in one of the 16-wide runs — `art/batch`, `sim/agent-seam`, `slice/spelling`, three names straight off mtg-w45's near-limit list — while nothing timed out in any 4-wide run. A 16-wide `--project balance` also produced a red run that named no test at all, `[vitest-worker]: Timeout calling "onTaskUpdate"`, which is the collating process being starved by the workers reporting to it.

**The right share depends on what else is in the run, and a constant cannot know that.** `npm run test:balance` on its own carries three sim pools and no unit files, and it prefers a wider one: four runs apiece put 16-wide at a 58s median with one 130s outlier, 4-wide at 57s, and 8-wide at 48s. A quarter is chosen for `npm test`, which is the command that flakes and the command everybody runs; the balance gate alone is a wash against the old default rather than a regression, and buying its last 15% needs a share that reads its surroundings. That is mtg-es2, and it is deliberately not a constant here.

**Thread count must not move a balance number, and that was checked rather than assumed.** A pool width that changed a win rate would be a much worse bug than the oversubscription it was sizing. `playIndex` is a pure function of (spec, index), `packages/sim/test/reproducibility.test.ts` asserts that serial, 2-, 4- and 5-wide runs agree digest for digest, and under mtg-czt the format-health gate's own printed reports — every gate, every band, every color-pair win rate, both subjects — came back byte-identical at widths 16, 8 and 4, and identical again between a full `npm test` and a bare `--project balance`. Check it that way if you ever move a width: the gate prints its report, so a diff of two reports is the whole proof.

**Playing it.** `npm run play` is the one command that puts a game in front of a person: it resolves a set (most recent `npm run slice`, else the committed `tideglass-reach` fixture, else a path you pass after `--`), stages it at `packages/ui/public/set.json`, and starts Vite. No API key and no Forge. Resolution and its failure messages live in `packages/ui/tools/resolve-set.ts` so they are testable; `play.ts` is only the part that touches the process. A set that fails `parseCard` is rejected before the server starts, because a bad set in the browser surfaces as a blank page with a console error.

**Showing a real deck.** `npm run lab` is the same arrangement one layer over: it resolves a deck artifact (most recent `decklab --artifact` run, else the committed `boros-aggro` deck, else a path after `--`), stages it at `packages/ui/public/deck.json`, and opens the Deck tab. The producer is `@mtg/decklab`'s `toDeckArtifact`, which is where the store's `image_uris` are read; the artifact then carries its own art URLs, so the page needs neither the card store nor a key. `@mtg/ui` deliberately depends on neither `@mtg/data` nor `@mtg/decklab` — `better-sqlite3` must never reach a browser bundle — so the artifact schema lives in `packages/ui/src/lab/deck-artifact.ts` and the two sides meet at a checked seam rather than a shared import. `DECK_ARTIFACT_VERSION` exists on both and is bumped together. A deck that fails the schema is rejected before Vite starts, naming the field.

Staging also caches the art. The artifact holds absolute Scryfall URLs, which is right for a portable document and wrong for a page: it makes the deck view depend on Scryfall being reachable _from wherever the viewer sits_, which is not the network that built the deck. `tools/stage-art.ts` pulls each illustration through `@mtg/image-cache` into `data/images/`, copies it into `public/art/`, and rewrites the staged copy's `src` to a relative path; the artifact on disk keeps its absolute URLs. A download that fails leaves that card's absolute URL in place and is reported by name, so the worst case is the behavior that existed before caching.

**The rules-text symbols go through the same path, and always end complete.** `packages/ui/src/card/symbols.ts` resolves a brace token to artwork through a named set, and nothing in this tree ever holds a copy of the glyph designs: `andrewgioia/mana`'s own README disclaims them as Wizards' copyright and Scryfall says the same of its SVGs. `scryfall` references the hosted file by URL, and it was the web face's default until a viewer behind a DNS filter turned every symbol into an empty box in the middle of a sentence, which contradicted the two promises the launchers already made about needing no network. So there is a third set: `local` addresses `symbols/{token}.svg` on this origin, and `tools/stage-symbols.ts` fills that directory the way `stage-art.ts` fills `public/art/` — 29 files through `@mtg/image-cache` into `data/images/`, then copied into the gitignored `public/symbols/`. **All 29 or none**: one symbol short would draw one empty box, so a single failure gives back `original`, the lab's own drawings, which need no network at all and are always complete. The launcher prints which of the two happened. The page learns it through a build-time substitution (`__MTG_SYMBOL_SET__`, defined in `packages/ui/vite.config.ts` from `MTG_SYMBOL_SET`) rather than a prop threaded through every card, and the substitution's absence — a bare `vite dev`, a `vitest` run, anything in Node — reads as `original`, so the floor is the safe set and a launcher can only raise it. The printed face keeps its own default, `PRINTED_SYMBOL_SET`: an emitted SVG is opened somewhere this repository is not, so it names the host outright or is published with `--symbols original`.

**One card, one vocabulary: the cost line goes through the registry too.** The title bar drew `card/anatomy.ts`'s own pip whatever set the face was painting with, while the rules box asked the registry, so a card could show a pale drawn `{2}` in its title bar over a real `{1}` in its rules text. Both faces now take two steps instead of one: `pipToken` says what a pip of a cost run is _called_ (`W`, `3`), and the registry says what that token is _drawn as_. `pipArt` survives as the floor under it, because the registry states `{0}`..`{20}` and a cost may name a larger generic amount. The same route carries `board/PlayerStatus.ts`'s floating mana pool (`mtg-bc2.45.5` closed on the pool spelling color letters; it has not regressed, and a set is that disagreement one layer down) and `routes/deck/DeckTile.ts`, whose cost is a real printing's string and goes through `symbolizeLine` — a hybrid or Phyrexian token the DSL cannot express is not in the registry, and `oracleChunks` leaves it printed as written rather than blank. A referenced pip carries `data-art="image"`, and `styles/symbols.ts` takes the identity disc and the ring off it, because the referenced file draws its own; that rule is written with two attribute selectors so it beats `styles/card.ts`'s `[data-pip]` colors on specificity rather than on sheet order.

`packages/card-render/test/parity.test.ts` names its symbol set (`original`, the set a published artifact prints) and scopes its pip patterns to the cost run, and both are load-bearing. The drawn set is what makes "the printed sheet draws real pip artwork rather than falling back to text" a claim worth holding, which is what that file's `drawn > 0` premise is for; the scoping is what stops a _rules-text_ symbol from entering a cost-line comparison, since each medium prints one its own way. Verified by mutation: deleting `glyphMarkup` from the printed pip still fails three assertions there.

**Card images: on-demand, cached, never mirrored.** `docs/research/prior-art-data-sources.md` settles the policy and the numbers say why: every one of the 38,623 printings carries an `art_crop` at about 67 KB, so a full mirror is ~2.5 GB (another ~3.3 GB for the `normal` faces) and 38,623 automated requests against terms that prohibit "undue burden … through the use of automated means". `@mtg/image-cache` keys on the URL rather than the bytes, which is what makes the cache self-maintaining: Scryfall's `?<timestamp>` changes when art is rescanned, so a re-ingest turns exactly the changed images into misses. The package deliberately has no third-party dependency — `@mtg/ui` must be able to take it without `better-sqlite3` reaching a browser bundle — and it is Node-only, so only `tools/` may import it, never anything under a `src/` that Vite bundles.

**Real cards are not DSL cards.** The deck view renders its own tile rather than reusing `card/Card.ts`, because a Scryfall card's rules text is free text the kernel cannot run and fabricating a DSL card from it would break the project's load-bearing invariant. What the two genuinely share — the art window and its pending frame — is `card/ArtSlot.ts`, which falls back to the hatched frame when a remote image fails to load.

**Web UI: two constraints that fail silently.** Both are consequences of having root configs only, and both cost real time to rediscover. (1) **No JSX anywhere.** The root tsconfig sets no `jsx` option and includes only `.ts`, so a `.tsx` file type-checks in your editor and escapes `npm run typecheck` entirely. React components are written with `createElement`. (2) **No global `lib: dom`.** The root tsconfig is `lib: ["ES2023"], types: ["node"]`, and adding DOM globally collides with `@types/node` on `fetch`, `Event` and friends. Reach DOM APIs through narrow structural interfaces that runtime-check what they receive, the way `packages/ui/src/app/router.ts` does. Do not "fix" either one by adding a per-package tsconfig.

**A page-initiated download reports nothing, so no surface may be built on one.** The DOM gives a page one way to hand somebody a file, an `a[download]` it clicks itself, and that call returns `undefined` whether a file landed on the disk or the browser dropped the request on the floor. There is no exception to catch, no promise to reject and no event to wait for, in any browser, so a helper that claims a file was saved is claiming something it cannot know. The environment makes that worse rather than being the cause of it: `src/app/router.ts` records why the app is a hash router, which is that the built page is a static file opened from `file://` as often as from a server, straight out of an `out/` run directory, and a download started from that origin is one a browser is entitled to refuse (a headless run and a window with downloads switched off refuse it too). We have not measured which browsers refuse it here, and the design does not turn on the answer — the point is that the page cannot find out. So `routes/deck/browser-file.ts`'s `saveTextFile` returns whether the browser was **asked**, which is the whole of what any code here can know, and no caller may say "saved". The rule that follows is about the surface rather than the helper: whatever the file would have contained stays on screen, selectable, at all times, and the download is a convenience laid over a route that always works. A button that is the only way to reach the content has moved the failure into the silence. `routes/deck/DeckFilePanel.ts` is the worked example — the decklist is in a textarea whether or not anybody presses anything.

**A change to the UI or the play UX is verified in a real browser, by the agent making it, before it is reported done.** Reading the stylesheet is not verification of a layout, and neither is a green `npm test`: **jsdom performs no layout**, so `getBoundingClientRect` is zeros and `scrollWidth` equals `clientWidth` on everything, and every ordinary test in `@mtg/ui` is blind to the size of anything. The failure that rule prevents is `mtg-s3re`, and it is a week old. `mtg-rgc.9`'s battlefield fix made a permanent stop being a seventh of its row, was verified by reading the CSS, and moved the hand row the other way: at 1024x768 a held card came out 71.5px wide against a permanent's 100px, which is under `styles/card.ts`'s `BOARD_RULES_MIN_REM` once the face's 16px of chrome comes off, so **not one of the seven cards in hand drew a word of rules text** while every permanent beside them drew all of it. The zone a player decides from was the one region on the table that could not be read, the suite was green, and it surfaced days later in a measurement pass that was looking for something else.

The command is `npx vitest run --project browser` — twenty-five files, thirty-one tests, under nine seconds of wall clock on a loaded box. It drives real `chrome-headless-shell` over CDP and asks it for the numbers. **Run it after a change to `@mtg/dsl` too, not only after a change to a layout.** The project is inside a bare `vitest run`, so `npm test` and CI do cover it, but the loop every lane in this repo actually runs is `--project unit`, and `unit` excludes `BROWSER_TESTS` by construction. A browser rig can therefore fail at collection time behind a green lane. That is `mtg-dg26`, and it took hours rather than weeks: `16964d4c` made every `@mtg/dsl` object schema strict, `packages/ui/test/card-loyalty.browser.test.ts` had been handing `parseCard` a token with a stray `artifact` key that `z.object` was silently dropping, and the whole file stopped collecting while the lane's own `--project unit` run stayed green. Write a new rig beside the ones in `packages/ui/test/play/*.browser.test.ts`, on `test/support/chrome.ts`'s `browserIt` and `measurePage` rather than a second copy of the harness; the file name has to end `.browser.test.ts`, because that suffix is the whole of the project's membership (`BROWSER_TESTS` in `vitest.config.ts`, checked against every rig on disk by `packages/ui/test/browser-project.test.ts`). Measure at 1024x768, 1280x800 and 1440x900, at four and at twelve permanents a side, and put the before and the after in the docblock as a table: a layout claim without the numbers behind it is the thing this rule exists to stop. Three things a rig owes the next reader. **A viewport meta tag in the page it writes**, or the emulated width is a lie every measurement inherits. **No art**: the only manifests that cover a set on this machine live under the gitignored `out/art/`, and a gate whose verdict reads them is a fact about the hard drive rather than about the repository — nothing measured moves anyway, since the art window is a ratio of the face and the pending frame occupies the same box. And a **budget stated at the call site** (120s is what these ask), never in `vitest.config.ts`.

A machine with no browser skips instead of failing, because a checkout with no browser cache is a normal checkout — so `MTG_REQUIRE_BROWSER=1` turns that skip into a red that names the missing path, the variable that moves it, and the command that installs it (`npx playwright install chromium-headless-shell`, about 90 MB from a third party, which is why no test run does it for you). CI sets the variable; a laptop does not. One rig is outside that switch and knows it: `packages/slice/test/ui-phone-scroll.browser.test.ts` carries its own copy of the skip rule, and `browser-project.test.ts` lists it as the one exception so the next copy fails instead of being the second.

**The play surface, and the four seams `mtg-bz2` splits it along.** The MTGO-style client is fourteen lanes over one route, and phase 0 gave them files they can hold at once. `routes/play/PlayView.ts` is a shell that composes and owns nothing: `rail.ts` is the legal-move list, `table.ts` is the board with the viewer's cards wired for clicking, `toolbar.ts` is the turn indicator and the stops, and `selection.ts` is the whole of the interaction state — with `pass.ts`, `picker.ts`, `choice-button.ts`, `PhaseBar.ts` and `stops.ts` under them. Two more sit under `selection.ts` and say where the focus ring goes: `focus.ts` is the one structural stand-in for a focusable element on this route, and `dismiss.ts` is the Escape and the outside press that a panel drawn over the board needs (`mtg-s9p`, `mtg-5jl`) — a second copy of either is a second answer to "where did the ring go", which is how a keyboard shortcut dies quietly. `styles/board.ts` split the same way, into `styles/board/` with one file per surface and `styles/board/index.ts` as the cascade order, which is load-bearing and says so. Add to the seam your lane is about; do not put a feature back into the shell.

**A stop asks a question; a beat only stops the clock.** They are different mechanisms and merging them would break one of them. A stop (`@mtg/kernel`'s `autopass.ts`) says "offer me my plays at this priority", and `mtg-hmy` qualified it with `canRespond` because a prompt whose only button is Pass is a page to dismiss rather than a decision. That closed the door on the obvious fix for combat being invisible: ticking `combatDamage` in the stop set buys a player with an empty hand nothing, since the kernel enumerates a pass and a mana ability there and no more. So `beats.ts` is the other instrument — `advance` halts, hands the session back with `beat` set, asks nothing, **records nothing**, and the next `advance` picks the loop up. Seed plus `choices` is still the entire record, so `replaySession` and `stateFingerprint` cannot tell a paced game from a hurried one, which is why the pause rides in `SessionOptions` beside the stop set and never in `GameState`. It is read off _events_ rather than steps because the damage step is entered every turn of every game and `combatDamageStep` fires there whether or not anybody attacked; `damageDealt` fires when damage was dealt. `yieldPriority`, `replaySession` and `undoTo` all drop it, each for a stated reason. `@mtg/netplay` does not set it at all: one player's beat would be the other player's wait. The phase bar draws the pause as a dotted underline and a phrase in the node's accessible name rather than a fifth mark, because the four marks are the stop cycle and pressing a node does not move the pause (`mtg-885` is the control that would).

**A beat is not always a combat moment, and that split the type in two** (`mtg-302`). The fourth beat is a **death**, filed after a creature was cast, answered with removal at a priority the player held no instant for, and put in a graveyard beside a death trigger's token inside one press — 48 of the 62 settle windows holding a death across 40 seeded games of the flagship halted on nothing that showed it, at a median of 139 events per window. Two consequences shape `beats.ts` rather than being details of it. A death **has no step**: the three combat beats each _are_ a turn-based action, so a bar holding a `Step` can mark them, and a bar that marked all thirteen nodes because a creature might die in one would make the same false statement in the other direction — so `BEAT_STEPS` is a `Record` total over `BeatKind` whose `death` entry is `null`, and a fifth beat cannot be added without stating which steps it belongs to. And a death **carries a payload**: the permanent has already left the battlefield by the time anybody draws the halt, so `Beat` is a tagged union (`{ kind: 'death'; oids }`) while `BeatKind` stays the flat vocabulary a `BeatSet` is made of. It fires for **every** permanent destroyed, whoever controlled it — a destroyed permanent is public, the option is session-wide and has no viewer to filter by, and the rail says each one as its controller's through `ownedName`, so a hotseat table reads right for whichever of the two people is holding the screen. The combat beat wins a batch that holds both, because the state-based actions have already run and the damage frame's board is the board with the dead creatures gone. `SessionOptions.watchCombat` is now `watchBeats`, for the reason the rename exists at all: it no longer holds only combat.

**Two machines, one server, and where the concealment lives.** `npm run netplay` deals a table, starts `@mtg/netplay` on **127.0.0.1**, and hands the staging and Vite to `play.ts`; Vite is the only listener another machine can reach, and it proxies `/api` to loopback, so the game server sets no CORS header and has no opinion about origins. Each seat gets a `randomUUID` in its URL (`#/play?table=<token>`) — a capability, not an account: the bead states no accounts and no matchmaking, and what the token buys is that one player cannot open the other player's board by editing a digit. The load-bearing part is that **the client no longer holds the position.** Hot-seat hides the opponent's hand at the projection layer, which is honest at one screen and is nothing across a wire; `@mtg/kernel`'s `visibility.ts` _removes_ it instead — `seatState` drops the objects behind both libraries and the other seat's hand, clears the generator and the seed, and `seatEvent` clears the seed out of `gameStarted`, which a payload test found and a docblock would not have. `packages/netplay/test/hidden-information.test.ts` plays a whole game and searches every payload's JSON for the name of every card that seat may not identify, with a positive control so an empty payload cannot pass. The wire is an index in and a position out, `at` refuses a stale click, and the server owns the bots because it owns the session. **`@mtg/ui`'s `src/` may name `@mtg/netplay` only with `import type`** — the barrel exports `serveTable`, which reaches `node:http` — the way the replay reader already names `@mtg/sim`; `packages/ui/test/net/isolation.test.ts` reads the tree and fails a value import. Undo is deliberately not offered over the wire: a rewind replays a shorter prefix, and that prefix holds the opponent's decisions.

**The legal-move rail survives the rebuild.** Direct manipulation is added beside the flat move list, never instead of it: the rail is the keyboard and screen-reader path, it is the complete enumeration (a pass, a mulligan, a declaration of nothing to declare have no object to hang a click on), and it is the handle `packages/ui/test/play/play.test.ts` drives a whole game through. Narrowing, reordering, restyling and moving it are in scope for any lane. Removing the `role="group"` or its `LEGAL_MOVES_LABEL` name is not, and `packages/ui/test/play/rail-contract.test.ts` fails by name if either goes. The reasoning is in `packages/ui/src/routes/play/rail.ts`, which is the file you would open to do it.

**Two legal moves must not read the same.** The rail is the complete enumeration and every entry submits its own index, which buys nothing when two entries carry the same words: one Emberflow Raider a side offered two casts of Lightning Lash with one visible sentence and one accessible name between them, and picking wrong burned your own creature (`mtg-cee`). `packages/ui/src/routes/play/naming.ts` is the one answer, and the rail, the stack zone and the staged cast panel all read it. A target is said as its controller's — `your Emberflow Raider`, `Bot's Emberflow Raider` — always rather than only on a collision, so a phrase is a fact about the object and not about what else happens to be in the list; the possessive itself is `log/narrate.ts`'s `seatPossessive`, the same one-copy rule as `seatVerb`, because a hot-seat table names both seats and no flag can be trusted to say which one is reading. A same-named permanent under the _same_ controller carries what tells it from its twin instead (`3/5 · 2 damage marked`), only when a twin is on the board and only when the two differ. **Two permanents nothing on the table separates read alike on purpose** — two untapped basic Mountains are one sentence twice — because that is the true statement about them and the choice is genuinely free.

**Two doors into the kernel, and only one recorded value.** `choose(session, index, …)` takes an index into `decision.options` and is what `replaySession` spends. `chooseAction(session, action, …)` takes a constructed action, for the surfaces that build a move out of clicks rather than finding it in a cartesian product; it is guarded by `validateAction`, resolves the action to its index and records _that_, so a board that fits under the enumeration cap replays from a list of integers whichever door it was played through. **The index is preferred and the action is the fallback.** A legal action the enumeration does not contain is refused with `ActionNotEnumeratedError` only when `decision.complete` — that is the kernel disagreeing with itself, and it belongs to nobody but the kernel. Where the enumeration _truncated_, the move has no index to prefer and records its canonical spelling instead (`mtg-y1t.2`), because refusing it would make the cap a rule about which legal moves exist. `canonicalAction` and `settledAction` are what keep two spellings of one declaration recording the same bytes. Two known holes: `@mtg/kernel`'s `backend.ts` still stringifies a recorded choice for the neutral contract, so a game that used the fallback records `[object Object]` and will not reopen (`mtg-2guj`); and a concession is legal from every decision and enumerated at none, so a concede control needs the enumeration to offer one.

**Two card renderers, one specification.** `@mtg/ui`'s `card/Card.ts` draws the on-screen face and `@mtg/card-render` draws the printed 63 x 88 mm SVG. ADR-0002 keeps them separate for a stated reason and pays for it with `packages/ui/src/card/anatomy.ts`, the single source of everything they must agree on: region order, the art window ratio, the card trim, the rarity seal outline, the pip run and the symbols it draws, the collector line. Color lives in `styles/tokens.ts` and identity in `card/identity.ts`, both already shared. A change to how a card _looks_ goes in the specification, never in one renderer; `packages/card-render/test/parity.test.ts` renders the same card through both and fails when they diverge.

**Spelling.** American, everywhere the repo writes its own words: doc comments, test titles, error messages, report headings, and every `.md` in the tree. Three things keep whatever they were written with. **Text that reaches a model**, because a prompt is an input and not decoration — `@mtg/llm` keys a fixture on `hash(system, prompt, schema)`, so editing one invalidates every recorded response behind it. That is wider than the files named `prompts.ts`: setgen's repair loop hands a failing slot's findings straight back to the model, and a `CARD_INVALID` finding quotes the DSL violation verbatim, so `@mtg/dsl`'s validator messages and `@mtg/setgen`'s finding messages are prompt text one hop away — `describeSlot` and a role's substitution note likewise. Rewording any of it is a deliberate change that re-records its fixtures and re-runs whatever depended on them, never a copy-edit. **Existing identifiers**, because `honoursDistinctSlots`, `summariseArchetypes`, `unrecognised` and the `'off-colour'` violation kind are exported API and serialized tags; renaming them is its own change with its own blast radius. **Recorded output and quoted sources** — fixtures, generated sets and reports, the eval transcript, a paper title, somebody else's URL — because rewriting those makes the record false. `packages/slice/test/spelling.test.ts` enforces this over every file git tracks — the index rather than the working tree, because the tree also holds the set `npm run play` stages and the images it caches, and a gate that goes red because somebody played a game is a gate that gets deleted. It names every exemption with its reason, whether that is a word in one file or a whole path; one it no longer needs fails the same test.

**Code style.** Immutable by default; pure functions over mutation. Discriminated unions narrowed by exhaustive `switch` with a `never` default. Explicit error handling — never swallow, never mask with defaults. Validate at every boundary (file, network, subprocess, LLM output). Files 200–400 lines typical, 800 hard max; functions under 50 lines. No placeholder code, no commented-out history.

**LLM calls.** Behind the `@mtg/llm` provider interface, never a direct SDK call from feature code. Three providers: `fixture` (recorded responses — the only one tests and CI may use, keeping runs hermetic and free), `claude-cli` (shells out to the local authenticated `claude -p --output-format json` binary; the default for local runs since no `ANTHROPIC_API_KEY` is set on this machine), and `anthropic-api` (`@anthropic-ai/sdk`, model `claude-fable-5`, requires `ANTHROPIC_API_KEY` validated at startup). Semantic judgment goes to the model; schema validation, retries, and budgets stay in code (ZFC).

`CompletionRequest.maxTokens` is a bound the `claude-cli` transport cannot enforce: that binary has no flag for it. So the transport states `--effort` (default `medium`, overridable per provider or with `MTG_LLM_EFFORT`) and passes `--tools ''`. Left at the binary's own effort, one `@mtg/decklab` selection round spent 15,555 output tokens and 238 seconds on an answer of about 3 KB and landed either side of the transport's five-minute timeout run to run; the same round at `medium` took 84s and 5,088 tokens. Do not answer a slow live call by raising `DEFAULT_CLI_TIMEOUT_MS` before checking what the call is being allowed to spend.

**Third-party engines.** Forge is GPL-3.0 and lives only under `tools/forge/` as a downloaded artifact invoked as a subprocess. Never vendor its source or link it. AGPL code (Manabrew, mtgdraftbots) is never copied at all. MIT sources (XMage, Argentum) may be ported with attribution in a header comment naming the file and license.

**Destructive commands.** Always write the fully expanded literal absolute path. No `$VAR`, no `~`, no `*` globs, no brace expansion in `rm`, `mv` onto an existing target, `find -delete`, `git clean`, `truncate`, or `>` redirects over real files. An empty variable turns `rm -rf $DIR/` into `rm -rf /`, and a glob deletes what it matches today rather than what you pictured. When a glob is how you found the targets, run the read-only match (`ls`, `find`) first, read the actual list, then delete the resolved paths explicitly. Pass this rule down to any sub-agent you dispatch.
